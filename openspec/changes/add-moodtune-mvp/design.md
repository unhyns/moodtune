## Context

그린필드 프로젝트 — 기존 코드, DB, 배포 이력이 없다. Next.js(App Router) + TypeScript + Tailwind CSS를 사용하며, 영구 데이터베이스는 두지 않는다 (`planning/md-design/04_TECHNICAL_DESIGN.md` §6). 배포 대상은 Vercel(서버리스)로 가정한다. 동기·배경은 proposal.md의 Why를 참고.

## Goals / Non-Goals

**Goals:**
- 사용자의 실제 Spotify 라이브러리를 기반으로, 항상 라이브러리 내 트랙만 추천하는 안전한 최소 아키텍처를 확립한다.
- 서버리스 배포 + DB 없음이라는 제약 아래에서 동작하는 세션/상태 전략을 확정한다.

**Non-Goals:**
- 캐싱 전략 고도화(짧은 TTL 서버 캐시 등)는 이번 change에서 다루지 않는다 — 필요해지면 후속 change.
- FR-10("다시 추천받기" 재요청)과 FR-6(자연어 입력의 실제 반영)의 구현은 이번 change 범위 밖이다. FR-10은 원본 입력 컨텍스트 전달 방식까지 포함해 다음 세션 이후 별도로 재설계하기로 의도적으로 보류한 것이며(충돌이 아닌 결정 — `planning/md-design/02_REQUIREMENTS_SPEC.md` Decisions Log 참고), FR-6은 Should로 제외됨. FR-11(수동 도시 입력)은 이번 MVP 범위에 포함되어 tasks.md에 반영한다.

## Decisions

### 1. 세션/토큰 저장: Stateless 서명 쿠키
서버리스 배포에서는 인스턴스 간 메모리를 공유할 수 없다. 서버 메모리 세션 + 쿠키 ID 방식은 인스턴스 재시작/스케일 아웃 시 세션이 유실되므로 기각하고, **액세스·리프레시 토큰을 직접 담은 암호화·서명된 http-only 쿠키**(stateless)를 채택한다.

### 2. `librarySample` 구성: 최근 좋아요 우선, 최대 50곡
전체 라이브러리를 매 요청마다 프롬프트에 넣는 것은 비용과 응답 품질에 나쁜 영향을 준다. **최근에 좋아요한 곡 최대 50개**를 기본 샘플로 사용한다. 완전 무작위 샘플링은 "지금 이 순간"과의 관련성이 낮아 기각했고, 장르 다양성 기반 샘플링은 추가 분류 로직이 필요해 이번 MVP 범위에는 과하다고 판단했다.

### 3. 기분·상황 퀵리플라이 옵션 확정
- 기분: 신남 / 차분함 / 우울함 / 집중 / 설렘
- 상황: 출근길 / 산책 / 카페 / 운동 / 드라이브

`02_REQUIREMENTS_SPEC.md`에 예시로 남아 있던 값을 그대로 채택한다. 목록이 작고 스펙(정확히 하나씩 선택)에는 영향을 주지 않아 이번 change 내에서 바로 확정했다. 하드코딩이 아니라 상수 배열로 분리해 구현하여, 데모 후 쉽게 조정할 수 있게 한다 (tasks 참고).

### 4. Input → Result 데이터 전달: URL 쿼리 파라미터
브라우저 저장소·전역 상태 라이브러리 없이, 추천 결과 표시에 필요한 최소 필드(`uri`, `name`, `artist`, `art`, `reason`)를 URL 쿼리 파라미터로 인코딩해 전달한다 (`04_TECHNICAL_DESIGN.md`에서 이미 확정된 결정을 그대로 채택). 필수 파라미터가 없으면 입력 화면으로 리다이렉트한다.

### 5. 배포 대상: Vercel (가정)
Next.js 프로젝트의 기본 배포 대상으로 Vercel을 가정한다. 결정 1(세션 저장)이 이 가정에 의존하므로, 배포 대상이 바뀌면 세션 저장 결정을 재검토해야 한다.

## Risks / Trade-offs

- [최근 좋아요 50곡으로만 샘플링] → 라이브러리가 크고 취향이 다양한 사용자에게는 추천이 편중될 수 있다. **Mitigation**: 데모 피드백을 본 뒤 후속 change에서 샘플링 전략을 고도화한다.
- [Stateless 쿠키에 토큰 직접 저장] → 쿠키 크기 제한(약 4KB) 안에 access·refresh 토큰이 들어가야 한다. **Mitigation**: 저장 필드를 최소화하고 만료 시각을 함께 검증한다.
- [Claude 재시도 1회 + 결정론적 폴백] → 폴백 경로가 자주 발생하면 추천 품질이 체감상 떨어질 수 있다. **Mitigation**: `isFallback` 플래그로 내부 구분을 남겨 향후 모니터링에 활용할 수 있게 한다 (로깅 인프라 자체는 이번 change 범위 밖).
- [기분·상황 옵션을 5개씩 고정] → 실제 사용자 테스트 없이 확정한 값이라 데모 후 조정이 필요할 수 있다. **Mitigation**: 옵션 값을 컴포넌트에 하드코딩하지 않고 별도 상수 배열로 분리한다.
