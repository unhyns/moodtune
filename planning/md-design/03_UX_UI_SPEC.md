# 03. UX/UI Spec — MoodTune

> Scope: 화면, 컴포넌트, 상호작용, 접근성 규칙.
> 다루지 않음: 기능 존재 여부(02), 구현 방식(04), 일정(05).

## 0. 디자인 톤
- Modern, minimal, polished, native-feeling (iOS-inspired), card-based.
- 모바일 우선 (외출 준비 중 짧게 사용하는 시나리오).

## 1. 화면 (Screens)

### 1.1 Landing
- **목적**: 서비스 소개 + Spotify 연동.
- **구성**: 로고/슬로건, 1~2줄 설명, Primary CTA "Spotify로 시작하기".
- **상태**: default / connecting(로딩) / error(로그인 거부·실패, 재시도 버튼 노출).

### 1.2 Input (기분·상황 입력)
- **목적**: 날씨 확인 + 기분·상황 선택 + 추천 요청.
- **구성**:
  - 날씨 배지 (아이콘 + 조건 + 기온, 자동 표시)
  - 기분 퀵리플라이 그룹 (단일 선택)
  - 상황 퀵리플라이 그룹 (단일 선택)
  - '직접 입력' 링크 (Tune Mine! 아래) — 칩 대신 자유 텍스트로 입력하는 별도 페이지(1.2a)로 이동
  - Primary CTA "추천받기" (기분 또는 상황 중 하나 이상 선택되기 전까지 비활성화)
- **상태**: 날씨 로딩 / 날씨 실패(수동 도시 입력 노출) / 입력 미완성(CTA disabled) / 제출 중(로딩).

### 1.2a Free Text Input (`/input/custom`, 자유 텍스트 입력)
- **목적**: 칩으로 고르기 어려운 상태를 한 문장으로 적어 추천 요청.
- **구성**:
  - 제목 "지금 상태를 직접 적어주세요"
  - 날씨 배지 (읽기 전용 — Input에서 이미 얻은 값만 표시, 새로 조회하지 않음. 없거나 실패면 "날씨 정보 없음")
  - 텍스트 입력창 (최대 200자, 글자 수 `n/200` 표시, 안내 문구 "입력한 내용은 추천 생성에 사용됩니다.")
  - Primary CTA "Tune Mine!" (빈 값·공백만이면 비활성화)
  - Input으로 돌아가는 링크 (항상 표시)
- **상태**: 입력 미완성(CTA disabled) / 제출 중(Input과 같은 로딩 팝업) / 실패(텍스트 유지 + 에러 문구 + 재시도, 빈 라이브러리는 별도 문구) / 세션 만료(Landing으로 이동).
- 칩 선택은 반영하지 않으며, 작성 중인 텍스트는 같은 탭 안에서 뒤로가기·새로고침 후에도 남는다. 결과 URL에는 입력 원문을 싣지 않는다.

### 1.3 Result (추천 결과)
- **목적**: 추천 곡 제시 + Spotify 이동 유도.
- **구성**:
  - 트랙 카드 (앨범아트, 곡명, 아티스트)
  - "이 곡을 추천한 이유" 한 줄 설명
  - Primary CTA "Spotify에서 재생하기"
  - Secondary 액션 "다시 추천받기"
- **상태**: 로딩(추천 생성 중) / success / error(추천 실패, 재시도 버튼) / invalid(필수 파라미터 없이 진입 → `/input`으로 자동 리다이렉트).

**확정**: 결과는 항상 1곡, 단일 히어로 카드 레이아웃으로 표시한다 (02 Decisions Log, 04 Data Model과 일치).

## 2. 컴포넌트 (Components)

| 컴포넌트 | 용도 | 비고 |
|----------|------|------|
| `PrimaryButton` | 각 화면의 핵심 액션 (시작하기/추천받기/재생하기) | 텍스트 필수, 아이콘 단독 금지 |
| `SecondaryButton` | 보조 액션 (다시 추천받기, 재시도) | |
| `QuickReplyChip` | 기분/상황 단일 선택 버튼 | 선택됨/선택안됨 상태 시각적 구분 |
| `WeatherBadge` | 날씨 조건+기온 표시 | 로딩/실패 상태 포함 |
| `TrackCard` | 추천 곡 표시 (앨범아트/제목/아티스트/이유) | Result 화면 핵심 요소 |
| `TextField` | 자연어 맥락 입력 | label 필수, placeholder만으로 대체 금지 |
| `LoadingIndicator` | 비동기 작업 중 표시 | 모든 API 호출 지점에 사용 |
| `ErrorBanner` | 실패 상태 안내 + 재시도 버튼 | 무응답/침묵 실패 금지 |

## 3. 상호작용 규칙 (Interaction Rules)
- 기분/상황 `QuickReplyChip`은 그룹 내 단일 선택(라디오 방식) — 다시 누르면 선택 해제 가능.
- 자유 텍스트 입력은 Input의 '직접 입력'으로 들어가는 별도 페이지에서만 하며, 칩과 함께 쓰지 않는다(칩 선택은 무시). 빈 값·공백만이면 제출할 수 없다.
- 자유 텍스트 제출은 버튼으로만 한다. Enter는 줄바꿈이라 한글 조합 중 Enter로 중복 제출되지 않는다.
- 기분, 상황 중 하나도 선택되지 않은 경우에만 Primary CTA는 비활성화 상태로 표시 (숨기지 않음).
- OAuth, 날씨 조회, AI 추천 등 모든 비동기 액션은 로딩 상태를 표시.
- 모든 실패 상태는 사람이 읽을 수 있는 메시지 + 재시도 경로 제공 (막다른 화면 금지).
- Result → Spotify 이동은 새 탭(웹) 또는 앱 딥링크로 열리며, 앱 내 재생은 구현하지 않음.

## 4. 접근성 규칙 (Accessibility)
- 모든 인터랙티브 요소는 텍스트 라벨을 가진다 (아이콘 단독 버튼 금지).
- 텍스트/배경 대비는 WCAG AA 기준을 만족한다.
- 탭 타겟은 모바일 기준 최소 44x44px 이상 확보 (외출 전 급하게 누르는 상황 고려).
- 로딩/에러 상태 변경은 스크린리더가 인지할 수 있도록 처리 (예: `aria-live` 영역).
- 이미지(앨범아트)는 대체 텍스트(곡명 - 아티스트)를 포함한다.
- 헤딩 구조는 페이지당 h1 1개 + 하위 섹션 h2로 시맨틱하게 구성한다.
